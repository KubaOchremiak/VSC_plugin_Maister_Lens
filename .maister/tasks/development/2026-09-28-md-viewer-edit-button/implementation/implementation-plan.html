TL;DR

  • There are 4 groups and 22 steps. Groups 1 (protocol + host), 2 (reader UI) and 3 (README/CHANGELOG) do not depend on each other and can run in parallel. Group 4 (test review + full regression) runs last.
  • Groups 1 and 2 are independent because reader.ts's post() takes unknown. The webview does not import the Message union.
  • Expect 13-22 new tests: unit, DOM and integration.

Key Decisions

  • Protocol and host share one group. The union member, validate case and dispatch arm form one contract, and the integration test covers them end to end.
  • The artifact DOM tests go in test/dom/surfaces.spec.ts, not in a new spec file. This follows minimal implementation and needs no harness changes.
  • Docs are a separate, test-free group. AC8 is checked by reading them in Group 4.
  • Group 4 runs the three suites once, in full. AC7 requires the existing tests to stay green without changes.

Open Questions / Risks

  • warningDoc-mode test assertions depend on the fixture. The DOM test uses the readerDocPayload() docs dir, and the integration test uses the real workspace folder. Do not fix the fixture.
  • warningreaderDoc.spec constraints: the strict nav.rd-crumbs button locator, the focusables slice(1,3) order, and no openSource in doc mode.
  • infoThe validateDoc refactor must keep the existing openDoc refusal regexes (/workspace folder/) green.
