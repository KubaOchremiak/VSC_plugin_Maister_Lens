TL;DR

This adds a read-only Project page, reached only from a sidebar item placed directly below Dashboard. For each workspace folder it shows a TL;DR with the goal and the tech stack, both taken verbatim from the Vision and Tech Stack entries in INDEX.md. Below that are grouped shortcuts to every .maister/docs/**/*.md. Docs open in the existing reader using a doc variant of the payload: "← Project" and "Project › path" post openProject, links between docs post openDoc, and there is no Source button. openDoc requires an exact workspace-folder URI plus a docs-relative, contained .md path. Restoring after a reload is out of scope.

Key Decisions

  • Entry point: the nav item is the only way in. maister.openProject is hidden from the palette, and neither new mode gets a title-bar button.
  • Modes: two new modes, project and doc, in the single TaskPanel. The doc location's field is named docsFolderUri so that the compiler flags every mode !== 'dashboard' site.
  • Links (Q1): classifyLink is unchanged apart from its base. A link inside the docs folder opens the doc. Any other relative link, including one into a task folder, opens in the editor.
  • Restore (Q2): out of scope. Every mode keeps the existing fallback to Dashboard.
  • Security (Q3): docRelPath is relative to .maister/docs. docsFolderUri must exactly match one of MessageContext.workspaceFolderUris. Paths go through containedRelPath and a .md allowlist.
  • TL;DR (Q4): no tech chips. The Tech Stack text is shown as written. This departs from the mockups.
  • Watcher: owned by TaskPanel. It honours watcherExclude, is debounced, and republishes the same location so the scroll position is kept.

Open Questions / Risks

  • warningIf the INDEX.md heading format drifts, the page shows the "missing" note.
  • warningThe link-base refactor touches every artifact render. render.test.ts must stay byte-identical.
  • infoSymlinks under the docs folder are not resolved. Containment is lexical.

Goal & Scope

Give users a one-click, always-rendered view of what the project is (goal and stack) and of every project doc and standard, without leaving Maister Lens.

In scope
  • The nav node and the hidden command
  • The project and doc panel modes, plus the doc RenderPayload variant
  • The projectMode bundle and the docs parser
  • The openProject and openDoc messages, and workspace-folder validation
  • The docs watcher, strings and tests
Out of scope
  • Editing docs and search
  • A Source button or raw-source view for docs
  • Palette and title-bar entries
  • Tech chips
  • Restoring after a reload (any mode)
  • Rendered routing for doc-to-task links
  • Symlink resolution, new dependencies and H1 labels

User Stories

As a developer, I want a Project entry directly below Dashboard so that I can recall the project goal and stack in seconds.
As a developer, I want shortcuts to every standard and project doc, grouped by folder, so that I can open the one I need without searching the Explorer.
As a developer, I want docs rendered like artifacts, with a "← Project" back control, so that reading stays in one consistent place.
As a multi-root user, I want one section per workspace folder so that the docs of each project are kept apart.

Title bar, watcher, link base
  • Title bar: the revealInExplorer when-clause also excludes project and doc. openArtifactSource stays limited to artifact mode. The new modes have no title-bar buttons.
  • Watcher: TaskPanel creates one .maister/docs/** watcher per workspace folder and disposes it with the panel. It skips folders excluded by watcherExclude and debounces events (about 200 ms). It republishes only in project mode, or in doc mode for the matching folder, and keeps the same location.
  • Link base: RenderTarget and readerPayload take a base directory and a kind. Artifact output stays byte-identical.
  • vscode stays out of src/model and render.ts.
Testing approach (2-8 tests per step group)
  • Parser: this repo's format with backticked suffixes, case, a missing section, entry or INDEX, and group order and labels
  • openDoc: accept a valid path. Reject a foreign root, .., %2e%2e, a backslash, an absolute path, .html, an empty path, and a bad anchor
  • classifyLink with the docs base: a doc link is an artifact link, a tasks link is a file link, and render.test.ts stays byte-identical
  • Playwright DOM: the project bundle with no chips, and the doc reader ("← Project", openDoc links, no Source button)
  • Integration: the project and doc modes, and a watcher republish that keeps the location
  • Existing tests: the harness BundleName, surfaces.spec.ts (projectMode plus the doc fixture), manifest.test.ts (the count stays at 9, the stale title is renamed, and when:false is asserted), and navTree.test.ts (roots goes from 1 to 2)

Test verification runs only the new tests.

Standards compliance
  • global: minimal-implementation, coding-style, validation, error-handling, commenting
  • frontend: components, css, accessibility
  • project/tech-stack: runtime dependencies are unchanged

Success Criteria

  • The page opens from the sidebar item below Dashboard and shows the goal and stack text from this repo's INDEX.md.
  • Every doc appears once, in the specified group order, and opens rendered with a working "← Project" control.
  • Links between docs open rendered. Other relative links open in the editor, and external links open in the browser.
  • openDoc rejects foreign roots, traversal and anything that is not .md.
  • Editing a doc refreshes the open view in place and keeps the scroll position.
  • Existing tests pass, apart from the deliberately updated ones.
