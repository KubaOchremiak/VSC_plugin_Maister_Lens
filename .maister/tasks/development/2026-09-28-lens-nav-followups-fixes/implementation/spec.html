TL;DR

Fix three Lens defects: the shim back button gets its own label, companion ../dashboard.html navigation works, and expanders collapse again. The Risks view is replaced by a Follow-ups view built only from status === 'completed' tasks, grouped by task, with a verdict breakdown from Task.verdict. Per-task Risks links open Follow-ups scoped to that task, and the Now-tree risks node is removed. The new model includes a shape-validated dashboard-data.js reader (JSON.parse, then yaml; never executed).

Key Decisions

  • A new string "← Lens Dashboard" for the shim button. FALLBACK.breadcrumb is unchanged.
  • Navigate hrefs resolve against hostBaseRelDir, and containment is still checked against the task root.
  • A refused navigate shows a VS Code warning and is also logged.
  • A global [hidden]{display:none !important} rule.
  • Risks is removed entirely: maister.openFollowUps, mode followUps, message openFollowUps. No aliases are kept.
  • dashboard-data.js: strip the prefix, then try JSON.parse and fall back to yaml. Keep an issue only if it has a string description, a severity of critical, warning or info, and a boolean fixed. Otherwise skip the file silently. The file is never executed.
  • "Completed" means status === 'completed'. There is no dismissal. §7 blocks, residual_issues and fixes_applied are excluded.
  • The Now-tree risks node is dropped. The per-task Risks links in the fallback view and the overview become Follow-ups links scoped to that task.
  • No cache. Counts are recomputed on an index refresh and when the dashboard-data.js watcher fires.
  • Row click: Issue and E2E rows open the task dashboard. Risk and Deferred rows open the task.

Open Questions / Risks

  • Uncommitted project-docs changes sit in the same files. Build on the working tree.
  • The deferred-decision regex is a heuristic.
  • dashboard-data.js files with unquoted keys or JS expressions are skipped by design (no JSON5 dependency).
  • The verification_context and dashboard-data.js shapes vary between Maister versions. Read every field defensively.
  • Navigate containment is security-relevant. Test both accept and refuse.

Out of scope

Technical approach
  • Bug 1: shim backLink() uses the new string.
  • Bug 2: MessageContext gains hostBaseRelDir. In artifact mode the panel supplies the task folder and dirname(artifactRelPath). The href follows the FR2 order, then goes to route(). Refusals trigger showWarningMessage. Task mode is unchanged.
  • Bug 4: CSS only.
  • Follow-ups data flow:
    1. parseState adds e2eFollowUp.
    2. The panel reads dashboard-data.js asynchronously for completed tasks. It is not stored in the index.
    3. collectFollowUps returns grouped rows plus verdict counts.
    4. The rows are posted to the followUps mode.
  • The KPI count reuses the same function and is recomputed on an index refresh or a watcher change. There is no cache.
Testing and standards
  • 2-8 focused tests per step group. Run only the new and affected tests.
  • The red tests (shim label, companion navigate, expander moved to Follow-ups) must go green.
  • New tests:
    • the FR2 navigate matrix (../dashboard.html accepted; ../../x, %2e%2e, https:, /abs and backslash refused) and the warning shown;

  • Standards: minimal-implementation, coding-style, error-handling, validation, conventions, accessibility, css.

Success criteria

  • Distinct back labels, and the native link opens the task dashboard.
  • An escaping href is refused with a warning.
  • The group arrows collapse and expand.
  • The Now tree has no risks node, and the checklist grep returns nothing.
  • The fixture shows the correct counts for the four sources, completed-only, plus the verdict breakdown. Non-JSON variants are skipped without error.
  • npm test, test:integration and test:dom all pass.
