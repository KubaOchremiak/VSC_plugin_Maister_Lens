← Auth token rotation › Implementation Plan
TL;DR

Four task groups replace long-lived refresh tokens with single-use rotating tokens. Storage change first, then the rotation job, reuse detection and client SDK updates. Existing sessions migrate lazily on next refresh.

Key decisions
  • Rotate on every use — limits replay to one request
  • Reuse revokes the whole family — standard theft response
Open questions & risks
  • Mobile clients on v3.x can't handle a rotated token
  • Clock skew on token expiry Resolved
